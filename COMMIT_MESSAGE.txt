feat: Standardize API responses and implement Redis-first pending registration

BREAKING CHANGES:
- All API responses now follow base response structure (status, message, statusCode, data/error)
- BusinessException now returns HTTP 500 (Internal Server Error) instead of 400
- Removed unused DTOs: ResendOtpDto, RefreshTokenRequestDto, SendOtpDto
- Changed HTTP methods: resend-otp, logout, refresh endpoints are now GET requests
- Removed DomainException (replaced with ValidationException and BusinessException)

Features:
- Implemented standardized API response structure
  * BaseResponseDto: Base structure for all responses
  * SuccessResponseDto: Wraps success responses with status, message, statusCode, data
  * ErrorResponseDto: Standardized error responses with status, message, statusCode, error
  * ResponseInterceptor: Automatically wraps all success responses globally

- Redis-first pending registration logic
  * OtpService.savePending(): Redis-first with PostgreSQL fallback
  * OtpService.getPending(): Retrieves pending registration from Redis or DB
  * OtpService.deletePending(): Removes pending registration from both stores
  * Automatic TTL expiration in Redis (5 minutes)

- Pending registration cleanup service
  * PendingCleanupService: Cron job runs every 5 minutes
  * Cleans up expired pending registrations from PostgreSQL
  * Prevents database bloat from stale registration data

- Exception handling improvements
  * BusinessException: Returns HTTP 500 for server-side errors
  * ValidationException: Returns HTTP 400 for client-side validation errors
  * HttpExceptionFilter: Formats all errors using ErrorResponseDto structure
  * PhoneAlreadyExistsException: Now extends ValidationException with field-level errors

- Swagger documentation updates
  * All endpoints show base response structure in Swagger
  * Success responses show SuccessResponseDto wrapper with data field
  * Error responses show ErrorResponseDto with proper error codes
  * Added specific error examples matching actual error codes:
    - RESEND_COOLDOWN_ACTIVE
    - OTP_DAILY_LIMIT_PHONE
    - OTP_DAILY_LIMIT_IP
    - INVALID_OTP, OTP_EXPIRED, OTP_ATTEMPTS_EXCEEDED
    - PHONE_ALREADY_EXISTS

- Authentication endpoint improvements
  * GET /auth/resend-otp: Changed from POST, no body required
  * GET /auth/logout: Changed from POST, no body required
  * GET /auth/refresh: Changed from POST, refreshToken as query parameter
  * POST /auth/resend-otp-credentials: New endpoint for expired OTP token resend

- DTO improvements
  * RegisterLeadResponseDto: Added retryAfter field (renamed from resendCooldownSeconds)
  * All DTOs: Made Swagger-rich with @ApiProperty decorators
  * Removed unused DTOs: ResendOtpDto, RefreshTokenRequestDto, SendOtpDto

- Code cleanup
  * Removed DomainException (consolidated exception handling)
  * Removed unused SendOtpDto file
  * Updated all imports and references

Technical Details:
- ResponseInterceptor registered globally in main.ts
- HttpExceptionFilter uses ErrorResponseDto for all error responses
- Redis keys: pending:<phone> with 5-minute TTL
- PostgreSQL fallback for pending registrations when Redis unavailable
- ScheduleModule added to AuthModule for cron job support
